# FORMA HOUSE — конструктор дома, калькулятор стоимости и CRM для строительной компании

Готовый веб-сервис для компании, которая строит частные дома. Посетитель выбирает проект, настраивает параметры в пошаговом конструкторе, получает предварительную стоимость и оставляет заявку. Менеджер получает заявку с полным набором параметров: проект, площадь, этажность, спальни, технология, комплектация, опции, регион, сроки, бюджет и контакты.

**FORMA HOUSE** — демонстрационный бренд. Название, логотип, цвета, контакты, тексты и цены меняются в админ-панели без изменения кода.

## Возможности

**Публичный сайт**

- Главная: hero, путь клиента, CTA калькулятора, избранные проекты, технологии, комплектации, демо-отзывы, FAQ.
- `/projects` — каталог с фильтрами по площади, этажности, спальням, цене и опциям (гараж, терраса, кабинет, второй свет, панорамные окна). Фильтрует без перезагрузки, состояние хранится в URL.
- `/projects/[slug]` — страница проекта: галерея с лайтбоксом, планировки, характеристики, стоимость в каждой комплектации, технология, опции, FAQ, похожие проекты.
- `/calculator` — конструктор из 7 шагов с живой ценой, sticky-сводкой (на мобильном — нижняя панель), расчётом на сервере, разбивкой стоимости и формой заявки. С параметром `?project=slug` подставляет параметры проекта.
- `/technology`, `/build`, `/about`, `/contacts`, `/faq`, `/privacy`, `/terms`, страница 404.

**Админ-панель** (`/admin`)

- Dashboard: новые заявки, заявки за сегодня и за неделю, число расчётов, конверсия «расчёт → заявка», график за 14 дней, воронка, последние заявки.
- Заявки (CRM): фильтр по статусам, поиск, пагинация, карточка клиента, смена статуса, комментарии менеджера, история событий, экспорт в CSV (одной заявки и всего списка).
- Проекты: создание, редактирование, публикация, скрытие, удаление. Загрузка главного изображения, галереи и планировок с сортировкой и alt-текстами. SEO-поля.
- Ценообразование: цена м² по технологиям, коэффициенты комплектаций и этажности, опции (фиксированная цена или цена за м²), параметры расчёта. Блок «Проверка формулы» пересчитывает пример на лету.
- Настройки: название, логотип, слоган, описание, телефон, email, адрес, режим работы, Telegram, WhatsApp, VK, основной и акцентный цвет, текст футера, SEO. Плюс FAQ, смена пароля, управление администраторами и статус интеграций.

## Быстрый старт

```bash
# 1. Зависимости (postinstall сам выполнит prisma generate)
npm install

# 2. Переменные окружения
cp .env.example .env
#    укажите DATABASE_URL и AUTH_SECRET (openssl rand -base64 48)

# 3. База данных: миграции и демо-данные
npx prisma migrate deploy
npm run db:seed

# 4. Запуск в режиме разработки
npm run dev
```

Сайт откроется на http://localhost:3000, админка — на http://localhost:3000/admin.

Seed создаёт администратора из `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`. По умолчанию это `admin@forma-house.ru` / `ChangeMe-2026!`. **Смените пароль после первого входа.**

### Создание базы данных

```bash
createdb forma
# или через psql:
psql -U postgres -c "CREATE DATABASE forma;"
```

### Миграции

```bash
npm run db:migrate    # разработка: создать и применить миграцию после правки schema.prisma
npm run db:deploy     # production: применить существующие миграции
npm run db:reset      # пересоздать БД и заново выполнить seed (удаляет все данные)
```

### Seed

```bash
npm run db:seed
```

Seed загружает 9 проектов (8 опубликованных и 1 черновик), 4 технологии, 4 комплектации, 3 типа дома, 12 опций, параметры расчёта, FAQ, 9 демо-заявок с историей и около 50 расчётов для графиков. Повторный запуск пересоздаёт демо-контент, администраторов не трогает.

### Создание администратора

```bash
npm run admin:create -- --email owner@company.ru --password "Strong-Pass-2026" --name "Анна"
```

Если email уже есть, скрипт сбросит пароль и завершит все сессии этого администратора. Добавлять администраторов можно и в разделе «Настройки».

## Переменные окружения

| Переменная | Обязательна | Описание |
| --- | --- | --- |
| `DATABASE_URL` | да | строка подключения к PostgreSQL |
| `AUTH_SECRET` | да | секрет для HMAC сессионных токенов, минимум 32 символа |
| `NEXT_PUBLIC_SITE_URL` | да | публичный адрес сайта для canonical, sitemap и OpenGraph |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | нет | уведомления о заявках в Telegram. Если пусто, канал выключен |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `NOTIFY_EMAIL_TO` | нет | email-уведомления. Канал выключен, пока не заданы `SMTP_HOST` и `NOTIFY_EMAIL_TO` |
| `STORAGE_DRIVER` | нет | `local` (по умолчанию) или `s3` |
| `STORAGE_LOCAL_DIR` | нет | каталог локального хранилища, по умолчанию `storage/uploads` |
| `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_PUBLIC_URL` | при `s3` | S3-совместимое хранилище: Yandex Object Storage, Selectel, MinIO, AWS |
| `NEXT_PUBLIC_YANDEX_METRIKA_ID` | нет | счётчик Яндекс Метрики |
| `NEXT_PUBLIC_GA_ID` | нет | Google Analytics 4 (`G-XXXX`) |
| `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD` | нет | администратор, которого создаёт seed |

Секреты берутся только из `.env` и не попадают в браузер: в клиентский бандл уходят лишь переменные с префиксом `NEXT_PUBLIC_`.

## Как считается стоимость

Цены хранятся в БД и редактируются в разделе «Цены». Формула — в `lib/pricing/engine.ts`:

```
база         = площадь × цена м² технологии («под ключ»)
этажность    = база × (коэффициент типа дома − 1)
комплектация = (база + этажность) × (коэффициент комплектации − 1)
спальни      = max(0, спальни − спален в базовой цене) × надбавка за спальню
опции        = Σ фиксированных цен + Σ (цена за м² × площадь)
итог         = округление(база + этажность + комплектация + спальни + опции)
```

Один и тот же движок работает в браузере (живая цена в конструкторе) и на сервере. Цена в заявке всегда пересчитывается на сервере по данным из БД, поэтому подменить её с клиента нельзя.

## Безопасность

- Серверная валидация Zod на каждом входе: публичные API, server actions, загрузки.
- Админка защищена трижды: `proxy.ts` (нет cookie → редирект или 401), серверная проверка сессии в layout, `assertAdmin()` в каждом server action и admin API.
- Пароли хешируются bcrypt (12 раундов). Если пользователь не найден, проверка всё равно тратит столько же времени, поэтому по ответу нельзя узнать, существует ли email.
- Сессии хранятся в БД, в cookie лежит случайный токен (httpOnly, SameSite=Lax, Secure в production), в базе — только его HMAC.
- Rate limiting: вход (по IP и по email), заявки (5 в минуту и 20 в час с одного IP), расчёты. Реализация в памяти процесса; для нескольких инстансов замените её на Redis в `lib/security/rate-limit.ts`.
- CSRF: route handlers проверяют Origin, server actions проверяются самим Next.js, cookie с SameSite=Lax.
- SQL-инъекции исключены: доступ к БД только через Prisma, сырых запросов нет.
- XSS: React экранирует вывод; JSON-LD экранирует `<`; цвета из настроек проходят строгую проверку формата; ссылки соцсетей — только `http(s)`.
- Загрузки: лимит 10 МБ, белый список MIME, проверка сигнатуры файла, перекодирование в WebP через sharp (EXIF и вложенные данные удаляются), случайные имена файлов, защита от path traversal.
- Защита от спама: honeypot-поле в формах.
- CSV-экспорт защищён от формул-инъекций.
- Заголовки безопасности: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, CSP `frame-ancestors`. Для `/admin` — `noindex`.

## Аналитика

Все события уходят через `trackEvent()` (`lib/analytics/events.ts`): в Яндекс Метрику как цели (`reachGoal`), в GA4 как события и в `window` как `CustomEvent("forma:analytics")`.

`calculator_start`, `calculator_step`, `calculator_complete`, `lead_form_open`, `lead_submitted`, `project_view`, `calculator_project_selected`.

Счётчики подключаются, только если заданы `NEXT_PUBLIC_YANDEX_METRIKA_ID` / `NEXT_PUBLIC_GA_ID`.

## Уведомления

После сохранения заявки уведомления уходят в фоне (`after()` из Next.js), так что ответ клиенту не ждёт внешних сервисов. Каналы описаны в `lib/notifications/`. Каждый включается своими переменными окружения, а ошибка одного канала не мешает остальным. Пример сообщения в Telegram:

```
Технология: Газобетон
Комплектация: Под ключ
Стоимость: 11 350 000 ₽
Источник: Калькулятор
```

## Production-сборка и деплой

```bash
npm ci
npx prisma migrate deploy
npm run build
npm run start            # порт задаётся через PORT или флаг -p
```

**VPS (Ubuntu + Nginx + PM2)**

1. Установите Node.js 22 и PostgreSQL, создайте базу и пользователя.
2. Склонируйте репозиторий, заполните `.env` (`NEXT_PUBLIC_SITE_URL` — боевой домен).
3. `npm ci && npx prisma migrate deploy && npm run build`
4. Создайте администратора: `npm run admin:create -- --email … --password …`. На пустой базе можно вместо этого выполнить `npm run db:seed`, чтобы получить демо-контент.
5. `pm2 start npm --name forma -- start`
6. Nginx как reverse proxy с HTTPS (Let's Encrypt). Передавайте `X-Forwarded-For` и `X-Forwarded-Host`: они нужны для rate limiting и проверки Origin. `client_max_body_size` — не меньше 50m, чтобы проходили загрузки галерей.
7. Каталог `storage/uploads` должен сохраняться между релизами. Второй вариант — включить `STORAGE_DRIVER=s3`.

**Vercel и другие serverless-платформы.** Нужны управляемый PostgreSQL (Neon, Supabase, Yandex Managed PostgreSQL) и `STORAGE_DRIVER=s3`, потому что файловая система там не сохраняется между запросами. Команда сборки: `npx prisma migrate deploy && npm run build`.

## Тестирование

```bash
npm run typecheck && npm run lint && npm test && npm run build
```

Unit-тесты проверяют формулу расчёта (коэффициенты, опции, округление, границы площади, неизвестные параметры) и схемы валидации. Перед релизом сквозные сценарии прогонялись в Chromium:

- каталог: фильтры, пустой результат, сброс;
- страница проекта и переход в конструктор с подстановкой параметров;
- весь калькулятор: ошибки валидации, маска телефона, сохранение заявки;
- мобильная версия и 404 для несуществующих и черновых проектов;
- админка: редирект без авторизации, 401 у API, неверный пароль, вход;
- проекты: создание, загрузка изображения, отказ для поддельного файла, публикация, скрытие, удаление;
- цены: изменение цены и её применение в расчёте, добавление и удаление опции;
- заявки: смена статуса, комментарий, экспорт CSV, фильтр;
- настройки: сохранение и отображение на сайте, проверка цвета;
- выход из админки.
