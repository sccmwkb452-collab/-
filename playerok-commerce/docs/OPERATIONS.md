# Эксплуатация

Ежедневная работа с системой: заказы, закупка, объявления, сообщения, режимы и аварийная остановка. Всё, что описано, доступно и в боте, и в веб-панели.

## Как устроена работа с PlayerOK

У PlayerOK нет открытого API для продавцов. Единственный известный способ автоматизации — неофициальная библиотека, которая обходит защиту площадки (DDoS-Guard) и работает от имени вашего аккаунта; это противоречит требованию не обходить ограничения и защиту аккаунта, поэтому система её не использует (подробно — [RESEARCH.md](RESEARCH.md)).

Поэтому PlayerOK подключён в режиме **«оператор + подсказки»**:

| Что | Как работает |
| --- | --- |
| Новые заказы | Вы вносите сделку в боте («🛒 Заказы → ➕») или в панели, либо загружаете CSV. Дальше всё автоматически: проверка, закупка (в рамках режима поставщика), выдача кода, учёт денег |
| Сообщения покупателей | Вы пересылаете текст в бот или вносите в панели — автоответчик готовит ответ, вы отправляете его кнопкой «Скопировать» |
| Публикация объявлений | Система готовит название, описание, цену, картинку и пошаговую инструкцию; после публикации вы указываете номер лота |
| Подтверждение сделок, поднятие лотов | Только вручную на площадке; бот напоминает |

Как только PlayerOK даст официальный API или письменное разрешение на другой метод, достаточно реализовать адаптер `integrations/marketplace` — остальная система уже готова (возможности переключаются флагами).

## Жизненный цикл заказа

```
Новый → Ожидает проверки → Ожидает закупки / Ожидает подтверждения → В обработке → Готов к выдаче → Выдан → Завершён
                                           ↘ Ошибка / Спор / Возврат / Отменён
```

| Статус | Что значит | Что сделать |
| --- | --- | --- |
| **Новый** | Заказ в очереди воркера | Ничего, обработка начнётся за секунды |
| **Ожидает проверки** | Сработала проверка (нет данных покупателя, цена ниже минимальной, категория не одобрена, автоматизация на паузе) | Прочитать причину в карточке → «Продолжить» или «Отменить» |
| **Ожидает подтверждения** | Поставщик в режиме «после подтверждения» | «Закупить» или «Куплю вручную» |
| **Ожидает закупки** | Нужна ручная закупка (у поставщика нет API, или лимит исчерпан) | Купить у поставщика → «Закуплено вручную» с фактической стоимостью; для кодов — «Добавить коды» |
| **В обработке** | Поставщик выполняет заказ | Воркер проверяет каждые 5 минут; можно «Проверить у поставщика» |
| **Готов к выдаче** | Код или результат готовы | Отправить покупателю в чате PlayerOK → «Выдано покупателю» |
| **Выдан** | Ждём подтверждения покупателя | После подтверждения на PlayerOK → «Покупатель подтвердил» (заказ завершится и попадёт в прибыль) |
| **Ошибка** | Сбой закупки или выдачи | «Повторить» или «Продолжить вручную»; причина в истории заказа |

Гарантии:

- повторный ввод той же сделки PlayerOK не создаёт второй заказ;
- закупка записывается в базу **до** обращения к поставщику; если поставщик не ответил (тайм-аут), закупка получает статус «неизвестно» и **никогда не повторяется автоматически** — сверьте её у поставщика (раздел «Ошибки интеграций»);
- один код выдаётся только одному заказу (резерв с блокировкой строки, уникальный отпечаток кода);
- полные коды хранятся зашифрованными; просмотр кода записывается в журнал, в Telegram код удаляется через `CODE_REVEAL_TTL_SECONDS` секунд.

## Поставщики и режимы закупки

| Режим | Поведение |
| --- | --- |
| Только мониторинг цен | Цены обновляются, закупок нет |
| Ручная закупка | Система рассчитывает, что и почём купить, вы покупаете сами |
| После подтверждения | Закупка через API после вашей кнопки «Закупить» |
| Автоматически в лимитах | Без подтверждения, только если: товару разрешена автозакупка, задан лимит одной закупки и суточный лимит, не превышено число операций в сутки, режим — боевой, аварийная остановка не включена |

Что подключено сейчас: курсы ЦБ РФ (работают), Fragment (мониторинг цен Stars/Premium, покупка только вручную — публичного API нет), VexBoost и Reloadly (адаптеры готовы, нужны ключи), KOSell (заблокирован: аренда аккаунтов нарушает правила Steam). Ключи вводятся на странице поставщика и хранятся зашифрованными; Reloadly сначала проверяйте в песочнице (`RELOADLY_SANDBOX=true`).

## Цены

Минимальная цена считается из полной себестоимости и всех процентов (комиссия PlayerOK по категории, платёжная комиссия, резерв на возвраты, комиссия вывода) так, чтобы выполнялись три порога: минимальная прибыль, минимальная маржа, минимальный ROI. Цену ниже минимальной сохранить нельзя ни в боте, ни в панели. Если цена поставщика устарела или курс валюты неизвестен, товар помечается и автоматические действия по нему останавливаются.

Цены конкурентов на PlayerOK система сама не собирает (нет API) — вносите их на карточке товара: запись сохраняется с датой и автором, рекомендуемая цена учитывает её.

## Объявления

1. Создать из товара → «Подготовить к публикации» (проверки: разрешённая категория, цена не ниже минимальной, есть остаток).
2. «Подтвердить предпросмотр» — без этого публикация невозможна.
3. «Опубликовать» → инструкция и кнопки копирования → разместить на PlayerOK → «Отметить опубликованным» с номером лота.
4. Первая массовая публикация требует отдельного подтверждения со списком всех объявлений.

## Автонастройки

14 функций в «⚙️ Автонастройки». У каждой: описание, статус интеграции, тексты и параметры, предпросмотр, тест (ничего не отправляет), история, сброс. Функции, которым нужен API PlayerOK, работают как подсказки оператору; «Автоподтверждение» помечено «Интеграция недоступна» и не включается.

## Тестовый и боевой режим

По умолчанию — **тестовый**: закупки имитируются (коды с префиксом `TEST-`), публикации не выполняются, тестовые заказы помечены 🧪 и не попадают в аналитику.

### Боевой режим

1. Проверьте режимы и лимиты всех поставщиков.
2. На сервере: `ALLOW_LIVE_OPERATIONS=true` в `backend/.env` → `docker compose up -d`.
3. Панель → «Безопасность» → «Включить боевой режим» (только владелец).

## Аварийная остановка

«Безопасность → Остановить всю автоматизацию» (или «🛡 Безопасность» в боте). Мгновенно останавливает закупки, автовыдачу, автонастройки и публикации; данные не удаляются, заказы продолжают приниматься и ждут вас. Снимается той же кнопкой.

## Мониторинг

- Шапка панели и «Главная панель»: состояние воркера и бота (по сигналам раз в 30 секунд).
- `https://api.<домен>/api/v1/health/ready` — для внешнего мониторинга (UptimeRobot и т. п.).
- «Ошибки интеграций»: сбои синхронизации, закупки с неизвестным результатом, упавшие фоновые задачи (кнопка «Повторить»), неотправленные уведомления.
- Логи: `docker compose logs -f api worker bot` (JSON, секреты и коды маскируются).

## Частые ситуации

| Ситуация | Решение |
| --- | --- |
| «Воркер не отвечает» | `docker compose ps`, `docker compose logs --tail 100 worker` |
| Бот молчит | Проверьте, что ваш ID в `OWNER_TELEGRAM_IDS` или аккаунт привязан в «Уведомлениях»; запущен только один экземпляр бота (второй сам завершится) |
| Вход в панель заблокирован | 5 неверных паролей → блокировка на 15 минут. Сброс пароля: `docker compose run --rm migrate python -m autocommerce.cli create-admin --email <ваш e-mail>` |
| Нужно сменить ключ шифрования | См. [SECURITY.md](SECURITY.md#ротация-ключей) |
