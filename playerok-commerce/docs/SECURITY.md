# Безопасность

## Секреты

- Все секреты — только в `backend/.env` на сервере (права `600`) или в менеджере секретов хостинга. В репозитории есть только `.env.example` без значений; `.env` исключён через `.gitignore`.
- Ключи поставщиков можно ввести в панели: они шифруются (Fernet, ключ `CREDENTIALS_KEY`) и больше никогда не показываются — только последние символы. Переменная окружения имеет приоритет над значением из панели.
- В Telegram секреты не отправляются; бот не запрашивает ключи в чате.
- В production без `SECRET_KEY` (≥ 32 символов) и `CREDENTIALS_KEY` API, воркер и бот не запускаются.

### Токен Telegram-бота

Если токен когда-либо был показан в переписке, на скриншоте или в логах, считайте его скомпрометированным: @BotFather → `/revoke` → выберите бота → новый токен в `BOT_TOKEN` → `docker compose up -d bot worker`. Старый токен перестаёт работать сразу.

## Что и как хранится

| Данные | Хранение |
| --- | --- |
| Пароли | Argon2id; для несуществующего e-mail выполняется такая же проверка (не видно по времени ответа, есть ли пользователь) |
| Сессии панели | В БД только хэш токена; cookie `HttpOnly; Secure; SameSite=Strict`, срок 12 ч, выход при бездействии 120 мин |
| Цифровые коды товаров | Зашифрованы; для поиска дублей — HMAC-отпечаток; в интерфейсах — маска `•••• 1234`; каждый просмотр полного кода записывается в журнал |
| Секреты 2FA | Зашифрованы |
| Ключи поставщиков | Зашифрованы (или только в переменных окружения) |
| Данные покупателей | Минимум: ник и данные для выдачи (например, @username) |

## Логи

Пароли, токены, ключи и полные коды в логи не попадают: фильтр маскирует их по названиям полей и по виду значений (токены Telegram, длинные ключи). Журнал операций хранит, кто и что сделал, без секретов.

## Вход и доступ

- Блокировка после 5 неверных паролей на 15 минут; ограничение частоты запросов на вход по IP и по e-mail.
- Двухфакторная аутентификация (TOTP) — включите в «Безопасность».
- CSRF: каждый изменяющий запрос содержит токен из отдельной cookie (double submit, HMAC от сессии).
- Роли: **Владелец** (всё), **Администратор** (всё, кроме пользователей), **Оператор** (заказы, коды, объявления, склад, сообщения, экспорт), **Наблюдатель** (только просмотр). Владелец создаётся только из консоли сервера.
- Бот пускает только ID из `OWNER_TELEGRAM_IDS` и привязанных пользователей (привязка — одноразовым кодом из панели, 15 минут); права в боте те же, что у роли в панели.
- Заголовки: `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, HSTS (production); панель дополнительно закрыта от индексации (`X-Robots-Tag: noindex`, `robots.txt`).

## Финансовая безопасность

- Тестовый режим по умолчанию; боевой — только при `ALLOW_LIVE_OPERATIONS=true` на сервере **и** переключателе владельца в панели.
- Автозакупка только для товаров с разрешением, в пределах лимита одной закупки, суточного лимита и числа операций; без лимитов режим «автоматически» не включается.
- Цена ниже минимальной (убыток или ниже порогов прибыли) не сохраняется.
- Закупки идемпотентны: намерение записывается до вызова поставщика, неизвестный результат не повторяется автоматически.
- Аварийная остановка всей автоматизации — одна кнопка в панели и в боте.

## Правила площадок

Система не обходит CAPTCHA, ограничения доступа и защиту аккаунтов. Источники без подтверждённого легального канала (аренда аккаунтов Steam, личные аккаунты подписок, предметы Roblox за деньги) заблокированы в каталоге; разблокировать категорию может только владелец после проверки правил.

## Ротация ключей

`CREDENTIALS_KEY`:

1. `python -m autocommerce.cli gen-key` → новый ключ.
2. `CREDENTIALS_KEY=<новый>,<старый>` (новый первым) → перезапуск.
3. `python -m autocommerce.cli rotate-keys` — перешифровывает ключи поставщиков, коды и секреты 2FA.
4. Удалите старый ключ из переменной → перезапуск.

`SECRET_KEY`: меняйте только при подозрении на утечку. Смена завершает все сессии панели (все войдут заново), делает недействительными неиспользованные коды привязки Telegram и сбрасывает защиту от повторной загрузки кодов: отпечатки уже загруженных кодов считались со старым ключом. После смены проверьте склад на дубли перед загрузкой новых партий.

## Резервные копии

Копии БД содержат зашифрованные коды и ключи — без `CREDENTIALS_KEY` их не прочитать. Храните `CREDENTIALS_KEY` отдельно от копий (например, в менеджере паролей): потеря ключа = потеря доступа к кодам на складе.
