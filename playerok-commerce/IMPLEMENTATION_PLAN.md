## 2. Ключевые выводы исследования

Подробно, с источниками и датами проверки — в [docs/RESEARCH.md](docs/RESEARCH.md).

### PlayerOK

* **Официального публичного API нет.** Документации для разработчиков на сайте и в поиске нет.
* `playerok.com` отдаёт 403 DDoS-Guard (геоблокировка) для серверов вне разрешённых регионов. Из среды разработки сайт и пользовательское соглашение недоступны.
* Единственный найденный способ программного доступа — неофициальная библиотека `PlayerokAPI` (GitHub `alleexxeeyy/PlayerokAPI`). Она работает через GraphQL сайта с cookie сессии, **подделывает TLS-отпечаток браузера** (`curl_cffi impersonate="chrome"`, `tls_requests`) и требует cookie `__ddg5_` — в коде она прямо названа «Cookie для обхода защиты DDoS-Guard».
* ТЗ запрещает обходить защиту площадки, а допустимость автоматизации правилами PlayerOK подтвердить не удалось. Поэтому **адаптер на базе неофициального GraphQL не реализован**.
* Реализован **ручной адаптер PlayerOK**: система готовит объявления (текст, цена, изображения, кнопка «Скопировать»), оператор публикует их сам и вносит номер лота. Заказы, сообщения и отзывы вносятся из бота или веб-панели либо импортируются из CSV. Все функции, которым нужен прямой доступ к PlayerOK, честно показывают «Интеграция недоступна» с причиной. Где возможно, вместо действия система даёт оператору готовую подсказку (текст ответа, напоминание).
* Интерфейс адаптеров (`integrations/marketplace/base.py`) позволяет подключить официальный API, когда он появится, без переделки остальной системы.

## 3. Архитектура (этап 2)

```
               ┌────────────── Vercel ──────────────┐
 Браузер ────► │ Next.js веб-панель (web/)          │
               │ /api/* → rewrite на backend         │
               └──────────────┬─────────────────────┘
                              │ HTTPS
        ┌──────────── постоянный хостинг (VPS, Docker Compose) ────────────┐
        │  api (FastAPI)   worker (фоновые задачи)   bot (aiogram, polling) │
        │        └──────────────┬─────────────┬───────────┘                │
        │                  PostgreSQL 16   Redis (необязательно)            │
        └──────────────────────────────────────────────────────────────────┘
```

* **Три отдельных процесса**: `api`, `worker`, `bot`. Управляются Docker Compose (`restart: unless-stopped`) или systemd.
* **Бот не зависит от сайта.** Сайт не запускает бота. Второй экземпляр бота не стартует: при запуске бот берёт advisory-lock в PostgreSQL и завершается, если блокировка занята.
* **Очередь задач** — таблица `automation_jobs` с `SELECT … FOR UPDATE SKIP LOCKED`, ключами дедупликации, повторами с экспоненциальной задержкой и лимитом попыток. Redis нужен только для состояний диалогов бота при нескольких репликах.
* **Уведомления** — transactional outbox (`notifications`): событие и уведомление пишутся в одной транзакции, worker отправляет их через Bot API с учётом 429 и повторов.
* **Деньги** — только `Decimal` и `NUMERIC(14,2)`, курсы — `NUMERIC(18,6)`.
* **Секреты** — только переменные окружения. Ключи поставщиков, которые вводятся в панели, хранятся зашифрованными (Fernet, ключ `CREDENTIALS_KEY`). Коды товаров тоже шифруются; в БД для проверки дублей хранится HMAC кода, в логах — только маска.
* **Тестовый режим** (`APP_MODE=test`, по умолчанию): закупки и публикации не выполняются по-настоящему, тестовые данные помечены во всех интерфейсах. Боевой режим включается только при `ALLOW_LIVE_OPERATIONS=true` и переключателе в панели.

## 5. Что нужно от владельца

1. **PlayerOK.** Официальный API или письменное подтверждение поддержки PlayerOK, что автоматизация через токен аккаунта разрешена и работает без обхода защиты. До этого — ручной режим.
2. **Telegram.** Токен бота от @BotFather (`BOT_TOKEN`) и ваш Telegram ID (`OWNER_TELEGRAM_IDS`).
3. **Поставщики.** API-ключ VexBoost (личный кабинет → API). Reloadly — client_id и client_secret (сначала песочница).
4. **Хостинг.** VPS для `api`/`worker`/`bot` и проект на Vercel для веб-панели (или доступы, чтобы я развернул сам).
5. **Шаблоны изображений** и, если есть, скриншот меню автонастроек.
