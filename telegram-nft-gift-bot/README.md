# NFT Gift Manager — Telegram-бот

Бот продаёт подписку за TON и помогает владельцу Telegram-аккаунта управлять своими NFT-подарками: смотреть список, готовить передачу и выполнять её **только после явного подтверждения владельца**.

- Python 3.12+, aiogram 3.31, SQLAlchemy 2 + Alembic, PostgreSQL 16
- Оплата в TON с проверкой транзакции в блокчейне на сервере
- Подключение аккаунта через официальный механизм **Telegram Business**
- Передача подарков через официальные методы Bot API `getBusinessAccountGifts` и `transferGift`
- Админ-панель по Telegram ID, аудит действий, Premium Emoji, Docker Compose

## Что важно знать заранее (ограничения Telegram и решения проекта)

| Требование | Как реализовано | Почему |
|---|---|---|
| Подключение своего аккаунта | Через **Telegram Business → Чат-боты**. Бот получает `business_connection` с правами, которые выбрал владелец. | Это единственный официальный способ дать боту действовать от имени аккаунта. Коды входа, облачный пароль и файлы сессии бот не запрашивает и не принимает. |
| Импорт tdata / файлов сессий | **Не реализован.** | Официального API нет. Сессия — это полный доступ к аккаунту, включая чаты и подарки, а бот не может проверить, кто её владелец. |
| «Купить аккаунт за 5 TON» (каталог аккаунтов, загрузка сессий админом) | **Не реализовано**, кнопки нет в меню, моделей `AccountProduct`/`AccountPurchase` нет. | Продажа доступа к чужим Telegram-аккаунтам нарушает [Условия Telegram](https://telegram.org/tos), а покупатель получает контроль над активами, владельца которых нельзя проверить. Ровно этот случай задание само запрещает: «механизм, позволяющий постороннему управлять чужими активами». Каждый подписчик подключает свой собственный аккаунт. |
| Передача обычных (не NFT) подарков | Показываются в списке как «обычный». | `transferGift` передаёт только **уникальные** подарки. Обычный подарок владелец может улучшить в приложении Telegram. |
| Комиссия за передачу | Показывается в предпросмотре. Списывается в **Telegram Stars** с баланса аккаунта. Нужно право «Передача звёзд». | Так устроен `transferGift` (`star_count`). |
| Получатель | @username, ссылка t.me/… или числовой ID. | Bot API находит по username только тех, кто писал боту. Числовой ID Telegram проверяет при передаче. Получатель должен быть активен в последние 24 часа (требование Telegram). |
| Telegram Business | Нужен Telegram Premium у владельца аккаунта. | Требование Telegram. |
| TON Connect | Счёт открывается ссылкой Tonkeeper (`https://app.tonkeeper.com/transfer/…`) и универсальной `ton://transfer/…` с суммой и комментарием. Её понимают Tonkeeper, MyTonWallet, Telegram Wallet и другие. | Оплата проверяется по блокчейну, а не по ответу кошелька, поэтому подделать подтверждение нельзя. Полный протокол TON Connect (сессия кошелька, `sendTransaction`) требует отдельной веб-страницы с manifest. Это возможное расширение: проверка платежей при нём не меняется. |
| Redis | Не используется. | Бот работает одним процессом (long polling). Лимиты и FSM хранятся в памяти. Для нескольких экземпляров замените `MemoryStorage` на `RedisStorage` в `bot/factory.py`. |

Если Telegram отклоняет операцию, бот **не показывает успех**. Он записывает ошибку в журнал и объясняет пользователю, что делать.

## Как работает сценарий

1. `/start`: приветствие с Premium Emoji и главное меню.
2. «💎 Купить подписку» → «Оплатить в TON»: бот создаёт счёт с уникальным идентификатором (`NFT-XXXXXXXXXXXX`) и сроком действия.
3. Пользователь платит из кошелька, указав идентификатор в комментарии.
4. Каждые `PAYMENT_POLL_SECONDS` бот читает входящие транзакции кошелька-получателя через toncenter. Подписка активируется, только если найдена транзакция с этим комментарием и суммой не меньше счёта. Кнопка «Проверить оплату» запускает ту же проверку сразу.
5. «🔐 Подключить аккаунт»: инструкция. Владелец добавляет бота в Настройки → Telegram Business → Чат-боты, бот получает подключение и сообщает о нём.
6. «🎁 Мои NFT-подарки»: список с номерами, изображением (стикер модели), ID и доступностью передачи.
7. Передать можно кнопкой («Передать» → получатель) или текстом: `передай 12 @alice`, `отправь подарок Plush Pepe #12 @alice`, `/transfer 12 123456789`.
8. Предпросмотр: подарок, получатель, комиссия, срок подтверждения (5 минут).
9. «✅ Подтвердить передачу»: выполняется `transferGift`, бот присылает результат или понятную ошибку. Повторное нажатие или старая кнопка повторно ничего не выполнят.
10. «📜 История операций», «👤 Личный кабинет», «💳 Мои платежи», «⚙️ Настройки» (продление, уведомления, отключение аккаунта), «🆘 Поддержка».

## Установка на Ubuntu VPS (Docker, рекомендуется)

Подойдёт любой VPS с Ubuntu 22.04/24.04, 1 ГБ RAM.

### 1. Подготовьте данные

- **Токен бота**: напишите [@BotFather](https://t.me/BotFather) → `/newbot` → скопируйте токен.
- **Включите Business Mode**: в @BotFather → `/mybots` → ваш бот → *Bot Settings* → *Business Mode* → *Turn on*. Без этого бота нельзя добавить в Telegram Business.
- **Ваш Telegram ID**: напишите [@userinfobot](https://t.me/userinfobot). Это число, не username.
- **Адрес TON-кошелька** для приёма оплаты (например, из Tonkeeper). Нужен только публичный адрес. Seed-фразу и приватный ключ никуда вводить не нужно.
- (Необязательно) API-ключ toncenter у [@tonapibot](https://t.me/tonapibot): с ним выше лимит запросов.

### 2. Загрузите проект на сервер

```bash
ssh root@ВАШ_IP
apt update && apt install -y git
git clone <URL_репозитория> /opt/nft-repo
cd /opt/nft-repo/telegram-nft-gift-bot
```

### 3. Первичная настройка

```bash
sh scripts/setup.sh
```

Скрипт установит Docker (если его нет), создаст `.env`, сгенерирует ключ шифрования и пароль базы данных.

Откройте `.env` и заполните три строки:

```bash
nano .env
```

```
BOT_TOKEN=123456:ABC...
ADMIN_IDS=111111111
TON_RECEIVER_ADDRESS=UQ...
```

Сохраните: `Ctrl+O`, `Enter`, `Ctrl+X`.

### 4. Запуск

```bash
docker compose up -d --build
docker compose logs -f bot      # логи; выход — Ctrl+C
```

Миграции базы данных применяются автоматически при каждом старте. Контейнеры перезапускаются сами после сбоя или перезагрузки сервера (`restart: unless-stopped`).

### Управление

```bash
docker compose ps                 # статус
docker compose restart bot        # перезапуск
docker compose down               # остановка (данные сохраняются)
git pull && docker compose up -d --build   # обновление
```

### Резервное копирование

```bash
sh scripts/backup_db.sh                                   # дамп в ./backups (хранятся 14 последних)
sh scripts/restore_db.sh backups/nft_bot_20261016_031700.sql.gz   # восстановление
```

Ежедневный бэкап через cron (`crontab -e`):

```
17 3 * * * cd /opt/nft-repo/telegram-nft-gift-bot && sh scripts/backup_db.sh >> backups/backup.log 2>&1
```

Храните копию `.env`, в первую очередь `ENCRYPTION_KEY`, отдельно от сервера. Без ключа сохранённые подключения не расшифруются, и владельцам придётся переподключить бота.

## Запуск без Docker (systemd)

```bash
apt install -y python3.12 python3.12-venv postgresql
sudo -u postgres psql -c "CREATE USER nft_bot WITH PASSWORD 'длинный_пароль';"
sudo -u postgres psql -c "CREATE DATABASE nft_bot OWNER nft_bot;"
useradd --system --home /opt/nft-gift-bot nftbot
cp -r telegram-nft-gift-bot /opt/nft-gift-bot && cd /opt/nft-gift-bot
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env && chmod 600 .env
.venv/bin/python scripts/generate_key.py       # вставьте результат в ENCRYPTION_KEY
nano .env                                       # DATABASE_URL=postgresql+asyncpg://nft_bot:пароль@localhost:5432/nft_bot
chown -R nftbot /opt/nft-gift-bot
cp deploy/nft-gift-bot.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now nft-gift-bot
journalctl -u nft-gift-bot -f
```

## Админ-панель

Доступ есть только у пользователей, чьи **числовые** ID перечислены в `ADMIN_IDS`. Username и любой ввод пользователя права не дают. Для остальных команды админки ведут себя как неизвестный текст.

| Команда | Действие |
|---|---|
| `/admin` | Статистика + разделы: пользователи, платежи, передачи, обращения, журнал аудита |
| `/user <id>` | Карточка пользователя (идентификаторы подключения не показываются никому) |
| `/grant <id> <дни>` | Выдать или продлить подписку |
| `/block <id>`, `/unblock <id>` | Блокировка |
| `/payments [статус]` | Платежи: `pending`, `paid`, `expired`, `cancelled`, `failed` |
| `/reply <№> <текст>` | Ответ на обращение в поддержку |
| `/set_price <TON>`, `/set_days <дни>` | Цена и срок подписки (действуют для новых счетов) |
| `/set_emoji <ключ> <id>` | Premium Emoji. ID проверяется в Telegram перед сохранением; `-` возвращает обычный эмодзи |
| `/check_emoji` | Проверка всех настроенных Premium Emoji |

Каждое действие администратора пишется в таблицу `admin_actions`. Об оплатах, ошибках передачи и новых обращениях админы получают уведомления.

### Premium Emoji

Ключи и запасные Unicode-эмодзи заданы в `nft_gift_bot/config/emoji.py`. Там стоят **демо-значения** (`DEMO_...`): это не настоящие ID, и в Telegram они не отправляются, вместо них показывается обычный эмодзи. Чтобы получить настоящий ID, перешлите сообщение с нужным эмодзи боту вроде @JsonDumpBot и возьмите `custom_emoji_id`. Затем `/set_emoji gift 5368…` или переменная `EMOJI_GIFT=` в `.env`. Ключи: `brand, subscription, payment_ok, payment, wallet, gift, account, security, error, warning, time, history, settings, support, admin, star`.

Эмодзи отправляются entity `custom_emoji` поверх Unicode-символа. Пользователи без Premium видят обычный эмодзи.

## Безопасность (результат аудита)

- **Секреты** только в `.env` (права `600`, в `.gitignore`). Приватный ключ кошелька не нужен: бот только читает входящие транзакции.
- **Шифрование**: ID Business-подключения хранится зашифрованным (Fernet, `ENCRYPTION_KEY`). Поиск идёт по HMAC-хэшу, открытый ID в базе не хранится.
- **Платежи**: подтверждение только по транзакции в блокчейне с уникальным комментарием и суммой не меньше счёта. Хэш транзакции уникален в БД, поэтому одной транзакцией нельзя оплатить два счёта. Переход `pending → paid` атомарный, повторная обработка невозможна. Транзакции, сделанные раньше создания счёта, не засчитываются. Скриншоты и «я оплатил» игнорируются.
- **Передачи**: перед каждой операцией проверяются активная подписка, активное подключение этого же пользователя, права Business-бота и принадлежность подарка. Передача выполняется только после нажатия кнопки, в течение 5 минут. Статус меняется атомарно (`pending → processing`), так что повторное нажатие ничего не повторит. Передачи самому себе запрещены. Скрытых и автоматических передач нет.
- **Отзыв доступа**: «Отключить аккаунт» стирает зашифрованный ID подключения. Бот также подсказывает удалить его в настройках Telegram Business. Отключение в Telegram сразу останавливает операции.
- **Изоляция данных**: все запросы фильтруются по `user_id` владельца. Чужой подарок или операция выглядят как «не найдено».
- **Ограничение частоты**: 30 действий в минуту на пользователя (`RATE_LIMIT_PER_MINUTE`).
- **Валидация ввода**: получатель (username, ID, ссылка), цены, сроки, ID эмодзи, длина обращений.
- **Логи**: структурированный JSON. Токены, ключи и `api_key=` маскируются фильтром. Содержимое переписки и ID подключений не логируются.
- **База данных**: PostgreSQL без открытых наружу портов. Бот запускается в контейнере не от root.
- **Окружения**: `ENVIRONMENT=test|production`. В production без `TON_RECEIVER_ADDRESS` бот не стартует, без `BOT_TOKEN` и `ENCRYPTION_KEY` не стартует нигде.
- Бот **не читает** бизнес-переписку владельца: обработчиков `business_message` нет.

## Разработка и тесты

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest                      # SQLite в памяти
TEST_DATABASE_URL=postgresql+asyncpg://user:pass@localhost:5432/test_db pytest   # на PostgreSQL
```

44 теста: платежи (сопоставление, повторная обработка, подмена хэша, недоплата, истечение), подписки (продление, истечение, уведомления), права доступа (админы по ID, изоляция пользователей, подключение без подписки, отзыв), подарки (подтверждение, двойное подтверждение, истечение, ошибки API, права, получатели, распознавание команд), безопасность и UI (шифрование, маскирование логов, rate limit, offsets custom emoji). Отдельно прогоняется сквозной тест через реальный `Dispatcher` aiogram: от `/start` до подтверждённой передачи.

Новая миграция после изменения моделей:

```bash
alembic revision --autogenerate -m "описание"
alembic upgrade head
```

## Структура

```
nft_gift_bot/
  bot/               сборка Dispatcher, тексты и UI (Premium Emoji), фоновые задачи, уведомления
  handlers/          обработчики Telegram (только приём событий и ответы)
  keyboards/         меню и inline-клавиатуры
  services/          бизнес-логика: платежи, подписки, настройки, шифрование, rate limit
  payments/          TON: суммы, счета, ссылки, клиент toncenter, проверка транзакций
  telegram_accounts/ подключение аккаунта через Telegram Business
  gifts/             подарки: Bot API, получатели, распознавание команд, передачи
  admin/             проверка прав администратора и операции админки с аудитом
  database/          базовые классы, сессии
  models/            SQLAlchemy-модели
  repositories/      запросы к БД
  middlewares/       сессия БД, пользователь, эмодзи, лимиты
  config/            настройки, эмодзи, логирование
alembic/             миграции
tests/               pytest
scripts/             setup, запуск, бэкап и восстановление, генерация ключа
deploy/              systemd unit
```

Модели: `User`, `Subscription`, `Payment`, `ConnectedAccount`, `Gift`, `GiftTransfer`, `AdminAction`, `SupportTicket`, `BotSettings`.
