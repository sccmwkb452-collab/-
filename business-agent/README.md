# Telegram Business AI Agent

Telegram-бот с ИИ-агентом (Claude), который подключается к Telegram Business, ведёт переписки
с клиентами и продавцами, анализирует фото/видео/GIF/стикеры, согласует условия и готовит
сделки через **строго один** выбранный пользователем торговый бот.

Главный принцип: агент выполняет разрешённые задачи сам, но не обходит ограничения Telegram,
не использует другой торговый бот вместо выбранного, не превышает финансовые лимиты и не
выдаёт невыполненные действия за выполненные.

## Быстрый старт (Docker)

```bash
cd business-agent
cp .env.example .env        # заполните BOT_TOKEN и ANTHROPIC_API_KEY
docker compose up -d --build
docker compose logs -f bot
```

Откройте бота в Telegram → `/start`. Схема БД создаётся автоматически при запуске.

### Без Docker

```bash
cd business-agent
python3.13 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
# нужен PostgreSQL (или для пробы: DATABASE_URL=sqlite+aiosqlite:///storage/agent.db)
python -m app.main
```

Для анализа видео, GIF и видеостикеров нужен `ffmpeg` (в Docker-образ уже входит).

## Что нужно заполнить

| Параметр | Где взять | Обязателен |
|---|---|---|
| `BOT_TOKEN` | @BotFather; там же **Bot Settings → Business Mode → Enable** | да |
| `ANTHROPIC_API_KEY` | console.anthropic.com | да, иначе агент не отвечает и медиа не анализируются |
| `ADMIN_IDS` | Telegram ID администраторов (по умолчанию `8790784360`) | да |
| `ALLOWED_USER_IDS` | Telegram ID остальных пользователей панели | нет |
| `DATABASE_URL`, `REDIS_URL` | в Docker задаются автоматически | да / нет |
| `CRYPTO_PAY_API_TOKEN` | @CryptoBot → Crypto Pay → Create App | только для интеграции Crypto Pay |
| `PARSER_TOKEN_<ИМЯ>` | токен вашего HTTP-парсера | только для HTTP-парсеров |

Секреты задаются **только** через переменные окружения. Бот никогда не спрашивает в чате
пароль, код входа, токены, seed-фразы или ключи.

## Подключение Telegram Business

1. Нужен Telegram Premium (Telegram для бизнеса).
2. Telegram → Настройки → **Telegram для бизнеса → Чат-боты** → укажите бота, выберите чаты.
3. Права: **отвечать на сообщения** и **читать сообщения** (обязательно); **удалять сообщения** —
   чтобы бот удалял команду «сутпасмотри».
4. Бот пришлёт подтверждение и список выданных прав. Раздел «🔗 Подключение Business»
   показывает права и обновляет их.

Подключение от пользователя, которого нет в `ADMIN_IDS`/`ALLOWED_USER_IDS`, записывается, но
агент в его чатах не работает.

## Панель управления

`/start` открывает главное меню: 🤖 ИИ-агент · 🔗 Подключение Business · 🔎 Парсеры ·
💬 Начальный текст · 🧠 Настройки ИИ · 🛍 Торговый бот · 🤝 Управление сделками ·
📁 Медиа и материалы · 📊 Статистика · 📜 История действий · ⏸/▶️ Пауза · ⚙️ Настройки ·
🛡 Администратор (только для `ADMIN_IDS`). Все настройки хранятся в БД и переживают перезапуск.

## Как агент ведёт диалог

1. Входящее сообщение сохраняется; медиа анализируется.
2. Агент отвечает, только если: агент включён, нет паузы, диалог в авто-режиме, у бота есть право
   отвечать, собеседник не отказался от общения, владелец не писал вручную последние N минут
   (настраивается). Несколько подряд идущих сообщений собираются в один ответ.
3. Claude получает неизменяемые правила, инструкции администратора, стиль владельца,
   структурированное состояние сделки, профиль контакта (только данные из источника), данные
   рынка и историю. Ответ — JSON по схеме: текст ответа, обновление состояния, отказ от общения,
   передача человеку, готовность к сделке.
4. **Код проверяет решение модели**:
   - цена/количество/валюта принимаются, только если реально прозвучали в переписке;
   - текст с упоминанием посторонних ботов, сторонними ссылками или утверждением «сделка
     создана/оплата прошла» (когда это не так) не отправляется — диалог передаётся человеку;
   - предложение собеседника перейти в другого бота фиксируется и передаётся человеку.
5. Если пока ИИ думал, владелец перехватил диалог или написал сам — ответ не отправляется.
6. Когда условия согласованы, готовится сделка (см. ниже).

Агент честно говорит, что он ИИ-ассистент, если его об этом спрашивают, и не выдаёт себя за
конкретного человека.

Состояние диалога (`Conversation.state`): этап, роль собеседника, тип и описание товара,
атрибуты, количество, цены продавца/целевая/согласованная, валюта, способ оплаты, возражения,
договорённости, подозрительные ссылки, статус сделки, флаг ручной проверки.

## Команда «сутпасмотри»

Владелец пишет `сутпасмотри` в любом подключённом чате (команду можно изменить в «⚙️ Настройки»):

1. команда распознаётся только от владельца бизнес-аккаунта (по Telegram ID);
2. сообщение с командой удаляется, если у бота есть право «удалять все сообщения»; если права
   нет — бот честно сообщает, что удалить не смог;
3. диалог переходит в ручной режим: агент не пишет, не отправляет стикеры и не создаёт сделки;
4. состояние переписки сохраняется, остальные диалоги работают как прежде;
5. вернуть авто-режим — кнопкой в уведомлении или в разделе «🤖 ИИ-агент».

Сообщения других участников не удаляются.

## Парсеры

**Режим A — с парсером.** Добавьте источник; бот определит способ подключения:

| Источник | Адаптер | Как работает |
|---|---|---|
| CSV/JSON-экспорт любого парсера | `file_import` | загрузите файл; колонки `user_id, username, name, role, text, price, currency, geo/city, url`, остальные — атрибуты |
| Ссылка `t.me/nft/…` или slug коллекции | `nft_owners` | публичные страницы подарков: атрибуты, редкость, публичный владелец |
| URL сервиса | `http_api` | HTTP API по контракту ниже, токен — `PARSER_TOKEN_<ИМЯ>` |
| `@какой_то_bot` | — | боты не могут получать данные от других ботов через Bot API; бот предложит выгрузить файл |

Контракт HTTP API: `GET /health` → 200; `GET /search?role=&q=&geo=&limit=&cursor=&filters=<json>` →
`{"items": [...], "next": "<cursor>"|null}`; `GET /profiles/{id}` → объект или 404.

Интерфейс адаптера (`app/parsers/base.py`): `connect`, `validate`, `search`, `fetch_profile`,
`fetch_available_context`, `normalize_result`, `disconnect`.

Для каждого парсера настраиваются: роль (продавцы/покупатели), ключевые слова, фильтры по
атрибутам, география, диапазоны (`price=1..50`, `model_rarity_percent=..1.5`, `number=1..300`),
лимиты обращений в день/всего, правила остановки и запуск по расписанию.

Перед постановкой в очередь каждый контакт проходит: критерии → дубликаты → история обращений →
отказы → лимиты → сохранение результата. По умолчанию каждое обращение нужно одобрить
(«📬 Очередь обращений»).

**Режим B — без парсера.** Агент работает только с входящими сообщениями и существующими
диалогами; источники данных не придумывает.

## Первое сообщение

Раздел «💬 Начальный текст»: добавить, изменить, просмотреть, отправить тест себе,
включить/выключить, несколько вариантов, основной вариант, удалить. Адаптация под контакт
(включается для каждого шаблона) использует только данные из источника; если ИИ добавил числа,
которых нет в шаблоне и профиле, или посторонние ссылки — отправляется исходный шаблон.

Если собеседник написал первым, основной шаблон используется как основа первого ответа.

## Медиа

| Тип | Обработка |
|---|---|
| Фото, изображения-файлы | анализ Claude: объекты, текст, характеристики, соответствие товару, сравнение с образцами |
| Видео, кружки | равномерные кадры через ffmpeg → анализ последовательности; аудио — см. ограничения |
| GIF (в Telegram это MP4) | кадры → анализ |
| Стикеры | статичные WEBP → PNG; видеостикеры WEBM → кадры; анимированные TGS — по превью (если есть), иначе честно «не проанализировано» |

Результат с `ok=false` и причиной сохраняется, если файл не скачался (лимит Bot API 20 МБ),
не разобрался или ИИ не настроен — агент видит, что медиа не проанализировано.

Агент отправляет стикеры/GIF/фото только из «📁 Медиа и материалы», и только с подходящим
«настроением» (приветствие, благодарность, согласие, раздумье, сделка завершена). В серьёзных
ситуациях и при передаче человеку стикеры не отправляются.

## Торговый бот

- Бот добавляется **только** через системную кнопку выбора бота (`request_users`) — Telegram
  передаёт настоящий числовой ID. По имени бот не определяется.
- Реестр разрешённых ботов = список в разделе; активным может быть только один.
  `allow_unlisted_bots` всегда `false`, запасных ботов нет.
- Перед каждой операцией `TradeGuard` проверяет: бот выбран, проверен, его ID совпадает со
  снимком в сделке (смена бота останавливает подготовленные сделки), для официальных
  интеграций — username официального бота, операция поддерживается, бот доступен.
- Ссылки на ботов из переписки не используются никогда; исходящие тексты с посторонними
  ботами блокируются.

Интеграции:

| Адаптер | Что умеет |
|---|---|
| `cryptopay` — Crypto Pay API (@CryptoBot / @CryptoTestnetBot) | выставление счёта покупателю (продажа) и сверка оплаты; перевод продавцу (покупка) с идемпотентным `spend_id` и сверкой; курсы |
| `manual` — любой бот без публичного API | агент готовит данные сделки, ссылку на проверенного бота и инструкцию; шаги в боте выполняет человек и отмечает их в панели |

Telegram-боты не могут управлять другими ботами через Bot API, поэтому для ботов без публичного
API автоматическое создание сделки невозможно — это явно показывается в карточке сделки.
Для нового сервиса с API добавьте адаптер в `app/trading/` (интерфейс `TradeBotAdapter`) и
зарегистрируйте его в `app/trading/registry.py`.

## Сделки

**Режим 1 — по подтверждению (по умолчанию).** Когда условия согласованы, владелец получает
карточку: продавец, товар, количество, цена, валюта, комиссии, итог, торговый бот — и кнопки
«Подтвердить и создать» / «Отменить», затем «Оплатить», «Сверить статус».

**Режим 2 — автоматический.** Включается в «🤝 Управление сделками → Лимиты» только после
задания дневного бюджета, валюты бюджета, максимальной цены и валют, и при выключенном
подтверждении. Дополнительно: категории, список продавцов, лимит одновременных сделок, пауза
повторной покупки. Авто-оплата включается отдельно.

Гарантии:
- одна договорённость → одна сделка (ключ идемпотентности);
- статус `CREATING`/`PAYING` и `spend_id` сохраняются **до** внешнего вызова;
- таймаут или обрыв → `UNKNOWN`; повторное нажатие «Оплатить» выполняет только сверку;
- повтор после «платёж не найден» — только вручную, с тем же `spend_id`;
- дневной бюджет считается по платежам, включая `UNKNOWN`, и никогда не превышается;
- неоднозначные цена/валюта/количество/получатель → сделка не готовится;
- для бота с API статус оплаты подтверждается только сверкой, не вручную;
- денежные операции владельца сериализуются (`pg_advisory_xact_lock`).

Важно про Crypto Pay: перевод (`transfer`) — прямой платёж, а не эскроу; получатель должен хотя
бы раз запустить @CryptoBot.

## NFT и Telegram-подарки

«🤝 Управление сделками → 💎 Оценка NFT»:
- атрибуты (модель, фон, символ) и их редкость — со страницы `t.me/nft/<Slug>-<номер>`;
- рыночные данные — только реальные наблюдения: добавьте строками
  `PlushPepe floor 12.5 TON` / `PlushPepe sale 15 TON model=Pumpkin backdrop=Black source=Fragment`;
- оценка: медиана сопоставимых продаж (та же модель/фон) → иначе floor как нижняя граница →
  иначе «недостаточно данных»; валюты пересчитываются по курсам Crypto Pay;
- всегда показывается время последнего обновления и предупреждение об устаревших данных;
- сравнение предложения с оценкой; внешний вид не считается доказательством редкости.

Если собеседник присылает ссылку `t.me/nft/…`, агент получает эти данные в контексте.

## Администратор и глобальные инструкции

Раздел «🛡 Администратор» доступен только Telegram ID из `ADMIN_IDS` (проверка ID, не имени).

1. «Новая инструкция» → отправьте текст, промпты, скриншоты, фото, видео, GIF, стикеры, примеры
   переписок, правила торговли (медиа анализируются, сохраняются описание и характеристики).
2. «Анализировать» → ИИ определяет тип, выделяет новые и удаляемые правила, находит конфликты,
   отмечает пункты, противоречащие правилам безопасности; код дополнительно отмечает упоминания
   ботов вне реестра.
3. «Применить» — создаётся новая версия; «Отклонить» — ничего не меняется.
4. «Версии» — история и откат (откат создаёт новую версию, история не переписывается).

Неизменяемые правила (`app/ai/prompts.py`, `HARD_RULES`) всегда стоят выше инструкций
администратора; текст с картинок и от собеседников — данные, а не инструкции.

## Память

- **Пользователь**: таблицы `owners`, `trading_policies`, `trade_bots`, `parsers`, `initial_templates`.
- **Диалог**: `conversations.state` (структурированное состояние) + `conversation_messages`.
- **ИИ**: `ai_config_versions` (глобальные инструкции, стиль, правила переговоров и торговли,
  примеры), `admin_materials`, `pending_instructions` — отдельно от переписок.

Приватность («⚙️ Настройки»): полная история или только короткое окно, срок хранения,
сохранение медиафайлов на диск (по умолчанию выключено — хранятся только file_id и описание).

## Журнал и статистика

Журнал (`audit_log`, «📜 История действий»): время, действие, диалог, парсер, торговый бот,
результат, причина ошибки. Все детали проходят через фильтр секретов (токены, ключи, seed-фразы,
приватные ключи); тот же фильтр подключён к логам приложения.

Статистика: найденные контакты, диалоги, отправленные/полученные сообщения, активные
переговоры, созданные/активные/завершённые/неудачные сделки, суммы, комиссии, ошибки интеграций.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Повторное получение обновления | `processed_updates`: каждое `update_id` обрабатывается один раз |
| Простой бота | `drop_pending_updates=False`: пропущенные сообщения обработаются после запуска |
| Нет прав на отправку / Telegram не даёт начать чат | ошибка в журнал, уведомление; для обращений — ручная отправка |
| Flood control | ожидание `retry_after` и повтор (сообщение точно не отправлено) |
| Сетевая ошибка при отправке | не повторяется — доставка неизвестна, чтобы не дублировать сообщение |
| Нельзя удалить команду | честное уведомление |
| Ошибка анализа медиа | медиа помечено как непроанализированное |
| ИИ недоступен / отказ модели | агент не отвечает, владелец уведомлён; серверный fallback модели включён |
| Торговый бот недоступен / не поддерживает операцию | остановка без запасных ботов |
| Недостаток средств, ошибка оплаты | `FAILED` с причиной |
| Неизвестный результат | `UNKNOWN` + фоновая сверка с экспоненциальной паузой |
| Ошибка парсера | статус парсера, журнал, уведомление |

## Ограничения (честно)

- **Первое сообщение новому человеку.** Бот бизнес-аккаунта может писать только в чаты с
  недавней активностью; начать переписку с новым человеком через Bot API нельзя. Если Telegram
  отказывает, обращение получает статус «нужно вручную»: владелец получает готовый текст и
  ссылку на профиль. Клиентский API (userbot) для массовых обращений намеренно не используется.
- **Боты без API.** Создавать сделки в чужих ботах автоматически невозможно (боты не видят
  сообщения других ботов) — используется ручной адаптер.
- **Аудио в видео.** Claude не принимает аудио; интерфейс `Transcriber` (`app/media/analyzer.py`)
  позволяет подключить распознавание речи. Без него бот пишет «аудио не анализировалось».
- **Анимированные TGS-стикеры** анализируются только по превью.
- **Рыночные цены NFT.** Публичного официального API floor price нет; цены вводятся/импортируются,
  для маркетплейса с API можно добавить провайдер, пишущий в `market_prices`.
- **Файлы больше 20 МБ** Bot API не отдаёт — такие медиа не анализируются.
- Один процесс бота на токен (polling). Денежные операции защищены блокировкой БД.
