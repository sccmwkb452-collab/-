# Безопасность

| Угроза | Защита | Где в коде |
| --- | --- | --- |
| Подмена пользователя в Mini App | Подпись `initData` проверяется на сервере (HMAC-SHA256, ключ из `WebAppData` и токена бота), срок жизни ограничен (`INIT_DATA_MAX_AGE_SECONDS`). Telegram ID, username и прочие поля берутся только из проверенной строки, лишние поля в теле запроса отклоняются (`extra=forbid`) | `shared/telegram_auth.py`, `api/deps.py` |
| Доступ к чужому заказу | Каждый запрос фильтрует по `user_id` из проверенной подписи. На отсутствующий и на чужой заказ ответ одинаковый — 404 | `services/orders.get_user_order`, тесты `test_foreign_order_is_not_accessible` |
| Поддельное «успешно оплачено» | Оплату подтверждает только событие провайдера с проверенной подписью или прямой запрос к провайдеру. Сумма, валюта и ссылка на платёж сверяются. Параметры возврата на страницу игнорируются | `payments/service.py` |
| Повторная обработка вебхука | Уникальный `(provider, event_id)` записывается в той же транзакции, что и изменения. Неподписанные события не получают `event_id` | `payment_webhook_events` |
| Подтасовка розыгрыша Lucky Buy | Commit-reveal: хэш сида сервера показывается при создании заказа, сид клиента фиксируется первой оплатой, розыгрыш (HMAC-SHA256) выполняется один раз в транзакции подтверждения оплаты. Сид сервера раскрывается только после розыгрыша, в том числе у отменённых заказов: их ещё может оживить поздняя оплата. Результат можно проверить в браузере | `services/lucky.py`, `lucky_draws` |
| Двойная доставка | Одна задача на заказ, единый `Idempotency-Key` для поставщика; неясные ошибки уходят оператору | `delivery/service.py` |
| Двойное списание бонусов и промокодов | Журнал бонусов с уникальным `dedup_key`, блокировки строк пользователя и промокода, резервирование использований | `services/bonuses.py`, `services/promo.py` |
| Злоупотребление рефералкой | Только новые пользователи, без самоприглашений и взаимных приглашений, награда после выполненного заказа в PRODUCTION, подарок пригласившему отклоняется, при возврате награда списывается | `services/referrals.py` |
| Админка | Вход без пароля: одноразовая ссылка из бота (5 мин, хранится только SHA-256), подпись Mini App или Login Widget. Сессия в cookie `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/admin`, в БД хранится хэш. Для изменяющих запросов нужен `X-CSRF-Token` (HMAC от сессии). Роли: поддержка / менеджер / владелец | `services/admin_auth.py`, `api/deps.py` |
| Произвол администратора | Действия «отметить оплаченным» нет. Каждое ручное действие пишется в `admin_audit_logs`: до и после, IP, user-agent. Возврат выполненного заказа доступен только владельцу | `api/routes/admin/*` |
| Секреты | Только в `.env` (права 600), в коде — `SecretStr`. В API и админку не отдаются (там только «настроен / не настроен»), в логах маскируются: токен бота, ключи, `initData`, подписи | `config.py`, `shared/masking.py`, `logging_setup.py` |
| Перебор и DoS | Лимиты nginx (`limit_req`) и приложения: на IP через Redis и на пользователя для создания заказов, платежей, тикетов и входа в админку | `api/ratelimit.py`, `deploy/nginx` |
| SQL-инъекции | Только SQLAlchemy с параметрами, сырые строки в запросы не попадают | — |
| XSS и встраивание | React экранирует вывод. CSP: `script-src 'self' https://telegram.org`, `frame-ancestors` — только Telegram. `nosniff`, HSTS, строгий `Referrer-Policy`. В сообщениях бота пользовательский текст экранируется | `deploy/nginx/snippets/security-headers.conf`, `notifications/templates.py` |
| CSV-инъекции в экспорте | Ячейки, начинающиеся с `= + - @`, экранируются | `admin/orders.export_csv` |
| CORS | По умолчанию выключен: Mini App, админка и API живут на одном домене | `CORS_ORIGINS` |
| Потеря данных | Ежедневный `pg_dump`, ротация, внешняя копия через rclone, страховочная копия перед обновлением и восстановлением | `deploy/scripts/backup.sh` |
| Ошибки запуска в проде | В `production` выключены `/api/docs` и dev-авторизация, контейнеры работают от непривилегированного пользователя, переход в PRODUCTION невозможен без реальных провайдеров | `api/app.py`, `deploy/backend.Dockerfile` |

## Рекомендации владельцу

* Включите в Telegram двухэтапную аутентификацию на аккаунтах администраторов: вход в админку привязан к ним.
* Не пересылайте ссылки входа из `/admin`.
* Регулярно проверяйте *Журнал действий* и *Настройки → Webhook-и* (отклонённые подписи).
* Храните копию `.env` и бэкапов вне сервера, в зашифрованном виде.
* Ограничьте SSH-доступ ключами и отключите вход по паролю.
